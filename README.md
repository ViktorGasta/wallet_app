# Wallet REST API Service

Асинхронное веб-приложение на базе **FastAPI**, предоставляющее REST API для управления балансом кошельков пользователей. Система спроектирована с учетом работы в высококонкурентной среде и полностью контейнеризирована.

## Стек технологий
* **Язык разработки:** Python 3.12
* **Веб-фреймворк:** FastAPI + Uvicorn (Асинхронный)
* **СУБД:** PostgreSQL 15
* **ORM:** SQLAlchemy 2.0 (Асинхронный режим + `asyncpg`)
* **Миграции:** Alembic
* **Валидация данных:** Pydantic V2
* **Тестирование:** pytest + pytest-asyncio + httpx
* **Линтеры/Анализаторы:** Flake8, Mypy (PEP8 Compliant)

## Архитектурные решения и Конкурентность

Для обеспечения целостности данных при параллельных запросах (изменение баланса одного и того же кошелька) реализованы два уровня защиты:

1. **Пессимистическая блокировка строк (`SELECT FOR UPDATE`)**: 
   В эндпоинте изменения баланса (`app/crud.py`) используется метод `.with_for_update()`. При поступлении нескольких параллельных запросов СУБД блокирует строку конкретного кошелька для первой транзакции. Остальные запросы выстраиваются в очередь и дожидаются фиксации (`COMMIT`), что полностью исключает проблему **Race Condition** (гонки данных) и потерю обновлений.
2. **Ограничение на уровне БД (`CheckConstraint`)**:
   На таблицу кошельков наложено ограничение `CheckConstraint("balance >= 0")`. Если из-за программной ошибки баланс попытается уйти в минус, PostgreSQL заблокирует транзакцию на физическом уровне и выполнит откат (`ROLLBACK`), гарантируя безопасность средств.
3. **Финансовая точность (`Decimal`)**:
   Для хранения и обработки сумм используется тип `Numeric(14, 2)` / `Decimal` вместо `Float`, что предотвращает потерю точности при округлении копеек.

## Быстрый запуск (Docker Compose)

Система поднимается одной командой. При старте Docker автоматически проверит доступность СУБД, применит миграции Alembic и запустит веб-сервер.

1. Убедитесь, что у вас запущен Docker Daemon.
2. В корневой директории проекта выполните команду:
   ```bash
   docker-compose up --build
   ```
3. Приложение будет доступно по адресу: **`http://localhost:8000`**
4. Интерактивная документация API (Swagger UI): **`http://localhost:8000/docs`**

## Примеры использования REST API

### 1. Получение баланса кошелька
* **Endpoint:** `GET /api/v1/wallets/<WALLET_UUID>`

**Пример запроса (cURL):**
```bash
curl -X 'GET' 'http://localhost:8000/api/v1/wallets/123e4567-e89b-12d3-a456-426614174000'
```

**Ответ (200 OK):**
```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "balance": 5000.50
}
```

### 2. Изменение баланса кошелька (DEPOSIT)
* **Endpoint:** `POST /api/v1/wallets/<WALLET_UUID>/operation`

**Пример запроса (cURL):**
```bash
curl -X 'POST' \
  'http://localhost:8000/api/v1/wallets/123e4567-e89b-12d3-a456-426614174000/operation' \
  -H 'Content-Type: application/json' \
  -d '{
  "operation_type": "DEPOSIT",
  "amount": 1000.00
}'
```

**Ответ (200 OK):**
```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "balance": 6000.50
}
```

### 3. Изменение баланса кошелька (WITHDRAW)
* **Endpoint:** `POST /api/v1/wallets/<WALLET_UUID>/operation`

**Пример запроса (cURL):**
```bash
curl -X 'POST' \
  'http://localhost:8000/api/v1/wallets/123e4567-e89b-12d3-a456-426614174000/operation' \
  -H 'Content-Type: application/json' \
  -d '{
  "operation_type": "WITHDRAW",
  "amount": 500.00
}'
```

## Обработка ошибок (HTTP Status Codes)

* **`404 Not Found`** — Кошелек с указанным UUID не существует.
  ```json
  {"detail": "Wallet not found"}
  ```
* **`400 Bad Request`** — Недостаточно средств для списания (WITHDRAW).
  ```json
  {"detail": "Insufficient funds"}
  ```
* **`422 Unprocessable Entity`** — Невалидный UUID кошелька или отрицательное/некорректное значение `amount`.

## Тестирование и Линтинг

Эндпоинты покрыты интеграционными тестами. Для изоляции во время тестов автоматически используется асинхронная база данных SQLite в памяти (`sqlite+aiosqlite:///:memory:`).

**Запуск тестов:**
```bash
# Установка тестовых зависимостей локально
pip install -r requirements.txt
pip install aiosqlite

# Запуск pytest
python -m pytest
```

Кодовая база полностью протестирована встроенными инструментами и удовлетворяет стандартам статического анализа типов:
* Проверка стиля кода: `flake8 app/` (0 ошибок)
* Проверка строгой типизации: `mypy app/` (0 ошибок)
